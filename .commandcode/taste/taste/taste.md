# Taste
- Likes character sprites large and prominent on screen — has repeatedly asked to scale them up (doubled minion sizes, then +50% more, then "tăng size nhân vật lên nữa tầm x2 lên"); default/realistic-scale sizes always feel too small to them, so err on the bigger side for characters/NPCs from the start. Confidence: 0.8
- Dislikes characters flip-flopping direction or bouncing back-and-forth ("xoay vong vong") — keep fighters facing one way (always face the enemy, even while retreating) and have looping characters wrap around the scene instead of bouncing at edges. Confidence: 0.7
- Wants all characters in a scene rendered at the same size — corrected depth-based scaling where figures in different rows came out smaller/larger ("các nhân vật phải bằng nhau chứ?"); vary only position, not sprite scale. Confidence: 0.6
- Fight/chase animations must be slow enough to read each action — complained twice that combat was over before they could see any slashing ("combat nhanh quá, tôi chưa thấy chém nhau gì cả?", later "sao tôi thấy combat nhanh vậy?"); pace so each approach → strike → retreat cycle takes seconds, not frames, and keep the whole fight a consistent watchable length (roughly 10–15s) even when the underlying data resolves in only one or two hits. Confidence: 0.8
- Even though the fight as a whole should stay watchable, individual attack motions must feel snappy and immediate — asked to shorten the strike itself ("trong combat tôi muốn chém nhau nhanh hơn, hiện tại delay?"), i.e. keep the overall match timeline but trim wind-up/active-attack and slash-effect windows so a swing lands instantly instead of feeling laggy. Confidence: 0.55
- Characters must never be overlapping/stacked on screen ("không để lên nhau chứ?") — spread them in an explicit formation (rows/columns, per-character offsets) so each sprite is individually visible. Confidence: 0.6
- Fight scenes must read as a real clash: both sides charge in from off-screen toward mid-screen and then fight in place there (paired up, slashing/shooting) — corrected the assistant when combatants ran past each other or kept retreating to their home sides ("đứng ở giữa chém nhau, bắn nhau, mới đúng"). Confidence: 0.8
- In-fight combatants should stay planted at their spot: charge in once at the start, then only switch attack animation — no per-hit lunge-forward/retreat "giật lùi" repositioning ("đứng yên tại chỗ chém nhau chứ?"). Confidence: 0.7
- Wants combat to feel "real", not scripted — pushes back on battle logic that resolves identically every time (fixed damage, crits on a fixed rhythm) and expects believable variance: damage jitter, random crits, dodges from both sides. Confidence: 0.6
- "Real" combat also means visceral visual feedback, not just numbers: pushed back when hits had no impact effects ("ko co hieu ung blood ah? cam giac chem / ban chua real lam") — add blood/particles, hit-stop, knockback, muzzle flash and multi-layer slash arcs so each strike visibly lands. Confidence: 0.7
- Wants nonstop motion with (almost) no dead time — after the fight pacing was fixed they still asked for continuous slashing with no gaps ("toi muon chem lien tuc nua, ko co khoang nghi"), so characters should keep swinging/acting in tight loops (pauses in the tens of ms, idle poses only as brief flashes) instead of standing around between actions. Confidence: 0.6
- Complains when hits/animations look mechanical: evenly spaced attacks read as wrong to them ("đánh nhau phải loạn xạ chứ?"), so vary timing (bursts plus pauses), offsets and sides per actor rather than using a uniform fixed interval. Confidence: 0.65
- Visually inspects "randomized" output and expects the variety to be genuinely independent per side/entity — caught that both teams picked the same sprite variant and tint from one shared index ("2 ben random khac nhau chu? toi thay giong nhau"); derive per-group variation from separate seeds/salts so counterparts never render identically. Confidence: 0.6
- Animation must look continuous, never jerky ("animation liên tục đi, hiện tại giật giật") — interpolate/ease transitions (sin or smoothstep) between poses, add subtle idle motion, and avoid snapping between static frames or holding a pose and jumping to the next. Confidence: 0.7
- Prefers sprite sheets kept as a single atlas image per character instead of hundreds of separate frame files — pushed back with "sao bạn ko làm spritesheet = 1 tấm hình thôi cho dễ?"; slice/load atlases and draw by source rect rather than generating per-frame PNGs. Confidence: 0.7
- Expects new assets/features to be wired into the app and left running (with a URL/way to try it) rather than delivered as standalone files to integrate later — prefers end-to-end "attach it so I can test now" delivery. Confidence: 0.6
- Wants one coherent troop/resource pool instead of parallel silos: any units tied up in one role must be counted in the same totals and unavailable elsewhere (e.g. minions assigned to guard territory must count against total minions and be subtracted from the force available to attack), rather than guarding only ever consuming a different unit type. Confidence: 0.55
- Expects game state to be surfaced visually where it applies, not only in management tabs — asked for symbols showing which territories have units stationed in them ("nên có hiện ký hiệu ... đàn em, lính ở những địa bàn nào được bỏ vào?"), so when units/resources are placed somewhere, render per-location indicators (map badges, per-territory sheet lines with counts) in addition to the tab that edits them. Confidence: 0.6
- Expects transient game UI (post-fight result popups and similar overlays) to auto-dismiss on a timer without any click — corrected the assistant after it replaced the existing 5s auto-close with manual-only close buttons ("toi ko thay tu dong tat? phai click x?"); when they ask "sau 5s tự tắt được không", implement the timed auto-close and keep manual X/XONG only as an optional early exit. Confidence: 0.65
- Communicates in Vietnamese — casual, usually typed without diacritics, mixing English tech terms ("fake data tren map 20 bang hoi co dia bang, de xem mau sac phan biet ntn?") — so reply in Vietnamese, matching that plain, direct register. Confidence: 0.65
- Any auto-distribution of forces/resources across held land must be fair per province, not one global pool split per tile: right after auto-assign shipped, the user questioned multi-province behavior ("cho chia quan giu data, neu nhieu tinh thanh khac thi sao? vd thanh pho hcm, tay ninh?") — a tax-ranked split over all tiles starves small provinces (3 tiles in HCM vs 20 in Tây Ninh). Split into equal per-province buckets first (remainder to the province with the highest-tax tile), then divide within each province by tax. Expect the user to probe scale/edge cases of new features immediately, so handle multi-region scaling from the start. Confidence: 0.6
- State-changing UI actions must immediately refresh the indicators that depend on them — the user reported the unread badge/notification dot staying stuck after tapping PHẢN CÔNG ("sau khi click pha cong ... notification ko refresh?"). After any action that alters underlying state (mark-as-read, claim, consume), re-fetch and re-render the dependent badges/counts/dots in place; never leave them stale until a manual reload or app restart. Confidence: 0.6
- For performance/FPS complaints, verify on a release build, not debug — when combat still felt laggy, the user asked to have the dev server switched to release mode to judge real performance ("bn chay mode release toi xem thu"); on perf reports, rebuild/restart the Flutter web server with `--release` and hand them the URL, since debug web builds are inherently slow. Confidence: 0.6
- Probes long-run balance for exploitability and wants hard caps so no one can snowball: asked to compute whether a few dedicated users could "outplay" everyone and whether there must be a maximum for đàn em + lính + tướng if someone holds full territory ("tinh toan thu xem, game co bi 1 vai users nao se outplay ko? maximun dan em + linh + tuong phai co neu chiem giu full dia ban?"); then immediately ordered all proposed caps implemented ("fix ca 3 di ?") — capped uy multiplier, crew cap 500, prestige multiplier cap. When adding economy/progression systems, include explicit upper bounds (unit caps, capped multipliers) rather than relying only on economic soft limits, and expect approval to apply the full set of fixes at once ("fix ca 3 di ?", later "lam het di" on a review list). Confidence: 0.75
- Wants AI-generated game art and delegates the creative direction to the assistant: proactively asked whether the assistant could set up its own Gemini Flash image-generation agent to produce more images from the assistant's own prompts ("tu tao 1 agent = gemini flash de generate them hinh anh ko theo prompt cua ban dc ko?") — i.e. when a capability is missing, they expect the assistant to build the bridge itself (small script calling an external AI API, key via env var) instead of just declining. Confidence: 0.5
